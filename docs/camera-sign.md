# 网页摄像头连续扫码（v0.5.0）

在“签到中心”或“群聊签到”点击“进入摄像头扫码签到”，勾选本轮用户，选择优先前置 / 后置摄像头，点击“启动摄像头并开始”。此时浏览器才申请摄像头权限；不申请麦克风。摄像头来自当前访问网页的设备，不是后台服务器的摄像头。

## 队列行为

- 首个有效二维码确定本轮活动编号，识别后自动为队首用户提交。兼容 URL 的 `id` / `aid` / `activeId` / `activePrimaryId` 与 `enc`，以及 `SIGNIN:` 字段格式。
- 动态二维码持续更新识别，提交过程中也继续识别；下次提交使用最新画面中的参数。没有二维码或画面滞后时等待，不拿此前的二维码继续提交。识别不到二维码不算用户签到失败。
- 每次只提交一位用户。成功退出队列；失败后至少等待 2.5 秒，重试当前用户。本轮第 **11** 次失败时移到待处理队列末尾，开始下一位。再次轮到该用户时本轮计数归零，累计失败及移至队尾次数保留，不丢弃失败用户。只有一个失败用户时仍会继续轮转，直到成功或手动停止。
- 已有本地成功记录的活动直接显示已签到，不重复提交。后台按用户再次读取活动、校验课程 / 群聊归属和实时签到方式，不能仅凭扫描任意活动编号提交；是否获取群聊仍由设置开关控制。
- 停止、离开扫码页、退出控制台、页面进入后台或全部完成时释放摄像头。等待授权期间也可停止，之后即使用户允许，迟到的摄像头流也会立即关闭。
- 已发出的请求不能撤回，停止后仍会显示其返回结果。网络连接或控制台会话异常时停止，避免在结果未知时继续自动提交；核对记录后可重新选择用户并开始。

页面显示待处理顺序、当前用户、累计失败、本轮失败和最后结果。队列只属于当前页面，不持久保存，刷新后需要重新选择。真实姓名与凭据仍只由服务器使用；显示名称沿用“设置 → 用户显示与签到来源”。

## 摄像头与 HTTPS

浏览器仅在安全上下文提供摄像头 API：[getUserMedia 文档](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)。

- 在服务器本机访问 `http://localhost:8765` / `http://127.0.0.1:8765` 可申请权限。
- 手机访问普通 HTTP 的局域网 IP 或 P2P 虚拟 IP 不具备这个例外，需要为自己的访问域名配置 HTTPS 与浏览器信任的证书。不要通过关闭浏览器安全检查实现。
- 可在既有服务前配置 Caddy / Nginx 等 HTTPS 反向代理，代理保留原始 Host，并将自己的域名加入 `AUTO_CHAOXING_ALLOWED_HOSTS`。HTTPS 部署设置 `AUTO_CHAOXING_HTTPS=1` 使登录 Cookie 带 Secure；修改环境变量需要重启服务。源服务地址和允许主机按实际网络部署填写，不把私人地址、证书私钥写入仓库。
- 请求权限被拒绝后可在浏览器站点设置中更改；没有摄像头、设备被占用或权限不满足时页面明确报错。

画面使用本地 Worker 和仓库已有的 jsQR 解码，最大处理边长 1280 像素，约每 350 毫秒尝试一帧，无并发解码。画面不上传、不录制、不持久保存；后端只接收解码后的文本。接口要求管理员会话与 CSRF，并限制单个用户的请求至少间隔 2 秒。相同活动以外的二维码不会改变本轮目标，更换活动需停止后重新开始。

## 边界与验证

本轮实现普通二维码签到的网页连续扫码流程，没有移植 Android 应用的人脸、滑块验证或其他平台验证流程。额外验证、活动结束、二维码过期等均以平台结果为准，不保证旧参数有效。未修改原有图片上传和手动签到入口。

离线测试覆盖两种二维码格式、真实解码器、跨账户隔离、真实姓名传参、重复签到、平台拒绝、11 次失败轮转、持续换码、串行请求、停止及迟到授权释放。离线模拟通过不代表实际摄像头、每个手机浏览器及超星真实签到已全部验证。

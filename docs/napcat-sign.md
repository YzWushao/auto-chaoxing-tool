# QQ 私聊签到（v0.14.2）

## 当前流程：直接进入摄像头扫码页

授权 QQ 私聊回复“扫码签到”，机器人直接发一个随机的一次性网页入口，不再在 QQ 中询问用户或活动。入口打开即领取有限扫码权限，不需要管理员登录；页面复用控制台“进入摄像头扫码签到”的用户勾选、摄像头描框、开始/停止和结果组件。

在网页手动勾选需要签到的用户，再点“开始扫描”申请摄像头权限。不会预先勾选或自动开启相机。界面按设置中的用户称呼显示，登录失效用户不能勾选。仅展示本次入口生成时授权范围内的用户称呼、登录可用状态与随机别名，仅额外提供本次入口可选点位的名称和学校位置，不提供真实账户 ID、Cookies、配置、课程或管理员权限。服务器在开始时独立校验用户，开始后固定所选用户，不能扩大范围；新增账户需要重新获取入口。每次最多 200 位候选用户，并发沿用扫码设置，最大 5。

不预先刷新活动列表；识别二维码后沿用摄像头签到服务，为每位所选用户核实活动归属、状态和必要验证，绑定首次识别的二维码活动。仅执行扫码类型活动，不能利用入口完成普通/位置签到、任意 URL 访问或修改配置。手机浏览器上传连续 JPEG，服务器识别和签到；现有安卓原生输入保持兼容。结果按所选用户显示，未勾选用户不会执行。

入口从生成起 5 分钟过期，不因领取或操作延期；原链接仅能领取一次。完成、主动停止、离开页面、QQ 回复“取消”、重新发送“扫码签到”/“签到”或修改 NapCat 设置后失效。停止或完成后，原浏览器可在原有效期加 60 秒内只读查看已产生的结果。新入口撤销同一 QQ 的旧入口。二维码处理中的平台验证与原流程一致，遇到仍需人工验证的用户会提示处理。

必须先在设置中填写“网页根地址”并添加超星账户，才能生成入口；未配置时会明确提示，不回退成 QQ 逐项选择。QQ 内置浏览器可能不支持摄像头，请在首次打开前将原始链接复制到系统浏览器。普通/位置签到继续使用控制台，QQ“签退”暂保留原有列表交互。下文的多选与活动范围入口属于兼容流程，不是新版“签到”的交互方式。

## 可选模型意图识别

在“设置 → QQ 签到 · NapCat → QQ 回复 · 模型意图识别”打开“模型介入”，填写 API 地址、API Key 和模型名称，测试后保存。此配置独立于刷课 API；默认关闭，旧配置升级后仍关闭。支持兼容 Chat Completions 且支持 JSON 输出的文本模型，协议字段参考 [Chat Completions API 文档](https://api-docs.deepseek.com/api/create-chat-completion/)。根地址补 `/v1/chat/completions`，版本或自定义路径补 `/chat/completions`，完整接口路径保持原样。模型 ID 按服务商提供的值填写，不预设服务商。测试会产生一次模型请求，仅使用虚构的三位测试用户，不发送 QQ 消息或执行签到。

标准“签到 / 签退 / 取消 / 下一页 / 上一页 / 跳过 / 继续”、序号、多选及“全选”直接处理，不调用模型。开启后，其余纯文字回复会结合当前阶段和当前页标签识别，例如“帮我签到”“选第一位和第二位”“下一页看看”。模型只可选择当前页显示的项目，直接序号指令可跨页。自然语言“所有用户 / 全部活动”先显示总数，需回复“确认全选”；也可重新选择或取消。姓名重名、条件或多步请求、接口失败、低置信度及格式异常不会执行操作，请改用标准序号。模型对自然语言的判断可能有误，明确序号最可控。

发给模型的内容限于当前回复、阶段、允许操作、项目总数与当前页序号/标签，不发送历史聊天、内部账户 ID、QQ 号、Cookies、密码、API Key、二维码图片、链接、完整手机号或点位坐标。显示姓名由已有的用户显示设置决定，手机号转换为尾号；学校、点位名及课程/活动标题会作为标签发送。请使用可信服务，费用与数据处理规则以该服务商为准。模型不能调用工具或任意接口，响应仅转换为现有会话指令；服务端独立校验阶段、序号、数量、授权和会话期限。图片始终走原有本地解码流程，不发送模型。

API Key 随 NapCat 配置加密保存在 SQLite，接口仅返回掩码；保留圆点保留旧值，关闭开关并清空 Key 后保存可删除。关闭模型后不请求 API，已有配置可留存。请求不使用环境代理、不跟随重定向，不记录请求/响应正文或凭据，设置连接/读取超时与响应大小上限；失败不自动重试。模型等待期间同一 QQ 消息仍按现有会话队列处理。修改 NapCat 配置会结束旧会话与扫码链接。

## 兼容会话：多选与全选

用户列表和活动列表均支持多选：`1,3,5`、`1 3 5`、`1、3、5`、`1-5`。
回复 `全选`、`全部` 或 `一键全选` 选择全部分页，重复序号只执行一次；序号越界或格式错误时整次选择不提交。
每批最多 200 位用户、1000 条用户活动任务。

选择多位用户后，会逐人刷新列表，同一来源、类型和阶段的同一活动合并显示，并标明所选用户数。
提交只覆盖实际拥有该活动的所选用户；已完成任务跳过。普通签到直接批量执行；一个用户失败会报告原因并继续其他用户。
拍照、手势、签到码及未解决的平台验证仍需网页处理，在批量汇总中明确标记，不自动假定成功。

二维码活动逐项询问：上传本活动的一张图片，为该活动的所选用户提交。
若仅部分用户失败，保留失败用户等待重发最新图片，成功用户不重复提交；回复 `跳过` 可处理下一活动。
也可打开该活动共用的一次性摄像头入口，完成后回 QQ 回复 `继续` 核对已完成结果并进入下一项。
共用入口只授权本次所选且共同拥有该活动的用户，沿用独立 Cookie、CSRF、单次领取和 5 分钟期限。
扫码页用“用户 1”等序号显示批量状态，不公开账户身份；并发沿用设置中的扫码并发数。

位置活动仍只选择一个预设点位，用于当前活动的所选用户；不同活动分别询问，不跨活动默默复用。
批量处理中可回复 `取消` 结束后续会话；正在等待平台返回的消息仍按接收顺序处理，已提交操作不能撤回。
完成后汇总成功、已完成、失败/待处理及跳过数量，并列出问题项。

## 兼容会话：预先限定活动的扫码入口

在“设置 → QQ 签到 · NapCat”填写“网页根地址”，格式为 `https://你的项目域名:端口`，无需路径；留空保留原有图片签到流程。该地址必须指向本项目，并在服务端允许的 Host 中。公网实时摄像头需要有效 HTTPS 证书。

授权 QQ 发送“签到”并选定用户后，单用户列表如有待处理二维码活动，会附上随机扫码链接。选定一个二维码活动后生成更窄的专用链接，同时撤销前一个入口。多用户批量则在逐项处理二维码活动时生成共用入口。通过入口打开独立扫码页，免管理员登录；点击“开始扫描”申请摄像头权限。浏览器连续上传 JPEG，服务器识别；安卓客户端也可本机识别并上传结果，参数解析、队列和签到由服务器执行。上传间隔沿用设置，后端图像模式最短 0.2 秒；每个用户失败提交至少间隔 2.5 秒。

权限只涵盖本次 QQ 显式所选用户与当时共同可用的二维码活动，首次有效提交绑定一个活动。页面只显示剩余时间和本次扫码状态，不能选择其他用户、读取课程、账户、配置、点位或控制台数据。本活动的所选用户处理完即关闭入口。平台自动验证沿用现有签到流程；若仍需额外验证，会提示相应用户转官方客户端或控制台处理，其余用户继续。

链接从生成起 5 分钟过期，领取后不续期，且只能被一个浏览器领取一次。签到成功、主动结束、离开页面、QQ 回复“取消”或重新发送“签到”、生成替代链接、修改 NapCat 设置后均失效。切后台结束扫描并撤销入口。原领取浏览器可在原期限后最多 60 秒内只读查询本次结果，不恢复扫码权限。进程重启也会撤销所有临时入口；不会恢复未完成的扫码操作。已发往平台的请求无法撤回。

令牌使用 256 位随机数，只放在 URL fragment 中，不进入 HTTP 请求路径、Referer 或访问日志；领取时换成独立 HttpOnly Cookie 与页面专用 CSRF，不产生管理员登录会话。服务端仅在内存保存令牌摘要与临时权限，不落盘到数据库。GET/HEAD 预览链接不会消费令牌；运行页面脚本并成功领取才消费。请勿转发原始入口，拿到它的人可领取本次有限扫码权限。如果 QQ 内置浏览器无法调用摄像头，先复制原始消息里的入口到系统浏览器打开；已经领取的原始入口不能再次领取，需回 QQ 重新获取。

实现按用户指令进行的课程签到；v0.4.0 可在设置中额外开启超星群聊签到。不监听 QQ 群聊，不控制刷课，不做辅助登录或主动状态推送。

## 连接

1. 在 NapCat 登录机器人 QQ，创建并启用 **WebSocket 服务端（正向 WS）**；消息格式选择 **Array**，设置独立 Token。
2. 跨主机使用时，让该监听地址和端口能从本项目主机访问。Docker 需正确映射 OneBot 端口，WebUI 管理端口不是 OneBot 端口。优先 P2P 私网；公网使用 WSS、有效证书、Token 和限制来源的防火墙，不开放无鉴权接口。
3. 本项目“设置 → QQ 签到 · NapCat”填写 `ws://<可达的 NAS 地址>:<OneBot 端口>/` 或 `wss://...`、Token、授权 QQ 号。路径按实际服务端配置填写。
4. 可先点“测试连接”：只调用 `get_login_info`，不发送 QQ 消息、不读取好友列表、不执行签到。勾选启用后“保存并应用”，再刷新连接状态。
5. 授权 QQ 主动私聊机器人发送“签到”。只有名单内的 QQ 可以操作；授权范围是本控制台管理的全部超星用户，**不固定绑定 QQ 与超星账户**，请只授权可信人员。

配置加密保存在 SQLite 的独立表，Token 只返回掩码，不导出到学校点位 JSON。密钥、QQ 白名单、私人地址不应写入公共源码。修改 NapCat 设置会结束旧会话；断线 5 秒后重连，接口请求不自动重发。运行入口仍为 `run.py`。

官方参考：[网络配置](https://napneko.github.io/config/basic)、[OneBot API](https://napneko.github.io/onebot/api)。

## 会话

```text
发送“签到”
  → 机器人询问“为谁签到”，列出超星用户和序号
  → 回复用户序号 / 多个序号 / 全选，实时刷新所选用户的签到活动
  → 回复活动序号 / 多个序号 / 全选
      普通：按所选用户批量执行，并回复平台结果
      二维码：逐活动上传图片，或使用该活动共用的扫码入口
      位置：逐活动列出“学校 · 点位”，选择一个点位后提交
```

始终先问为谁签到，即使只有一个用户。回复“签到”重置会话，回复“取消”结束。用户、活动和点位列表每页 12 项；回复“下一页”或“上一页”翻页，序号跨页保持一致，不限制已保存的学校与点位数量。5 分钟没有操作后会话过期。

“取消”结束后续对话，不能撤回已经提交给平台的操作；正在等待平台返回时，消息会按接收顺序处理。

普通活动如要求拍照不会被当作普通签到提交。手势、签到码、拍照仍需网页处理。需要先在网页端登录超星用户；QQ 不接收账号密码，不提供超星登录控制。

二维码请直接发送图片，不发附件或合并转发。图片最大 8 MB、2400 万像素，优先通过 NapCat 的 `download_file_stream` 获取已收到图片的字节，也兼容 `get_image` / `get_file` 的 Base64 返回；旧版服务可回退到刷新后的 QQ 图片 HTTPS 地址，包括新版 `multimedia.nt.qq.com.cn`。不会把 NAS 缓存路径当成本机路径读取，也不接受聊天文本指定任意文件或网址。随后在内存中处理方向、透明背景、缩放并转为 PNG，再本地解码 enc 并提交参数；不把原图上传超星、不使用第三方识别服务、不保存原图或二维码内容到日志。图片 CDN 下载请求不带 NapCat Token 或超星 Cookies。读取失败保留当前二维码会话，直接重发原图即可。

与网页保持一致，不额外拒绝活动编号不匹配或疑似过期的二维码。但“允许提交旧图”不代表平台接受旧 enc，更不是绕过时效校验；活动是否仍开放、参数是否有效以及最终签到结果，均以超星返回为准。

## 显示方式与超星群聊（历史）

设置 → 用户显示与签到来源，提供五种称呼：手机尾号、姓氏＋星号、完整姓名、星号＋名字、姓氏＋尾号。支持常见复姓，星号按实际字数补位。默认手机尾号，没有手机号时回退为 UID 尾号，不伪造手机号。网页与 QQ 使用相同设置；仅影响显示，SQLite 中的真实姓名、管理员登录名和提交给超星的姓名不变，历史平台日志不被重写。

群聊签到在 v0.14.2 已取消；以下为旧版历史实现记录：通过当前账户自己的群聊身份分页读取已加入的群组，每组检查最近最多 5 页消息，仅提取签到附件，不建立普通聊天消息仓库。活动详情过滤已结束签到，提交前再次验证群成员身份及活动状态；失败明确提示，不将读取失败误报为空列表。部分旧活动或平台额外验证仍可能要求官方客户端。

旧 `im.chaoxing.com/webim` 服务已不可用，适配使用当前超星提供的 IM 账户及环信服务。平台 Cookies 不发送给环信；群聊密码与访问令牌只用于本次请求，不写入 Git、日志或点位 JSON。

位置列表来自设置中已有的预设点位；每个点位保留其坐标系。QQ 提交前按网页默认策略统一转换为 BD-09，6 位小数不是实地精度保证。点位变更或删除后旧列表不能直接提交，需重新选择。请只选择本人实际所在位置，不用于伪造出勤。

QQ 与网页复用签到缓存、账户锁、登录失效处理和成功记录。真正调用签到接口前再次获取该活动的实时信息。重复 OneBot 消息 ID 在 SQLite 去重；机器人自身消息、群消息、未授权 QQ 和时间超过 2 分钟的旧事件被忽略。断线期间未确认的请求不会自动重发。若平台已接收但网络中断，结果可能暂时未知，请到官方客户端核对，不把网络失败理解为一定没有提交。

## 验证边界

测试使用虚构账号、二维码、点位及本地 OneBot WebSocket 服务验证流程，不提交真实签到。真实环境的连通与登录信息检查不等于三类真实签到全部成功；最终结果必须以超星平台返回和官方记录为准。


## v0.14.0 选择开关与学校位置

扫码页“全选用户”打开时选中可用用户并折叠列表，关闭恢复原先手选状态并展开。用户和点位列表随页面平铺，没有固定高度的内层滚动区域。所有选择在开始扫描后锁定。

“上报位置”默认关闭，关闭时列表折叠且开始请求不携带位置；开启时展开点位单选列表，必须选择一个点位才能开始。点位的经纬度由服务器读取，位置说明统一取父级学校的“学校位置”，不再使用点位说明。QQ 网页仅使用入口生成时授权的点位随机别名，不能传入任意坐标、其他点位或在开始后更换位置。点位已移除需重新获取入口；不要求位置时仍可关闭上报继续。


## v0.14.1 查询全部用户

回复“签到”检查控制台管理范围内全部超星用户，独立读取每人的课程活动（群聊签到已取消）。同一来源、阶段和类型的同一活动合并，按涉及用户数降序排列；每项后括号列出涉及用户，称呼使用全局用户显示设置。登录失效或读取失败会单独提示，继续检查其余用户。已完成状态仍会标注；不会因查询信息自动提交签到。列表支持翻页和原有活动多选，选择活动后才继续相应流程。标准“签到”“扫码签到”不调用模型；模型可将自然语言分别映射为查询或摄像头入口。

全员信息查询不按旧200人选择上限或批量执行任务数截断；执行批量仍保留1000条任务上限。昵称不以200字活动标题上限截断，过长回复拆成多条文本消息。查询信息、重新获取扫码入口或取消都会撤销同一QQ旧扫码入口。


## v0.14.2 取消群聊签到

当前仅获取、列出和处理课程签到。群聊设置开关和网页分页已移除，旧配置中曾开启的群聊字段在读取时强制关闭，直接请求群聊来源或提交旧群聊活动会报错。网页、QQ 全员信息查询、摄像头队列均不访问群聊消息接口。学校位置、全选/位置开关、昵称、课程签到与扫码功能继续沿用。文中的旧群聊说明仅记录历史实现，不代表当前支持。

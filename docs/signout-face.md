# 签退与本人照片验证（v0.7.0）

签到、滑块和扫码继续使用现有流程。地点沿用当前学校 / 预设点位、地图拾取、JSON 导入导出与坐标转换；没有替换地图或重新定义位置策略。二维码同时要求位置时，普通弹窗也展开已有点位 / 地图表单。

## 签退

- 活动列表兼容 `type=2` 与 `type=74`，签退按平台的关联签到编号等关系识别，不仅凭标题或 type 猜测。
- 签退有独立活动编号、成功记录和事件。签到成功不会将关联签退误记为已完成；提交前仍校验当前用户、活动归属、是否仍有效以及平台最终结果。
- 活动弹窗显示要求，可在已发布且当前用户能访问的关联签到 / 签退之间跳转。尚未发布或已不在有效列表中的目标不会被伪造为可执行活动。
- 课程和已启用的超星群聊使用同一处理方式。QQ 回复“签退”会先选择用户，再仅列出当前签退；原“签到”流程仍可显示带“签退”标识的活动。位置与二维码等参数继续按原方式填写。

## 本人照片

在活动弹窗点击“准备本人照片”，或遇到人脸要求后进入照片窗口：

1. 确认当前用户及活动，开启前置摄像头拍摄；也可通过手机的“选择当前照片”入口拍摄 / 选择当前照片。实时相机需要 HTTPS / localhost。
2. 画面只在设备内预览。拍照不会自动上传；勾选本人照片与发送用途，再点击“上传照片并继续”才发送。
3. 浏览器转为 JPEG，后台再次校验并重编码以移除 EXIF，使用所选账户上传超星云盘，再请求该活动的照片验证上下文。
4. 上传与取得上下文不等于人脸通过。后续签到携带上下文，只有超星最终明确成功 / 已完成才记录成功。

照片会发送到超星，平台可能保留副本；本机不保存原图、处理后照片或照片库。后台只保留绑定用户和活动的对象编号及上下文，最长 120 秒、最多 64 项；过期、取消或使用后不可复用。网页得到临时编号，不能自行指定其他用户的对象编号或通过结果。取消已经发出的上传不能撤销平台已接收的照片，但迟到返回的临时凭据会撤销。

一张普通拍摄照片不能证明活体检测通过，因此请求中的活体状态不会自行写成成功，也不生成官方设备证明。平台要求官方活体 / 设备校验，或照片未被接受时，通过“在官方页面处理”完成，再返回点击“核对结果”。核对只读取平台状态，不再次发起签到；未确认则不标记成功。

## 扫码队列恢复

人脸准备阶段暂时释放扫码镜头，保留已成功用户与待处理顺序，避免手机前后镜头争用。照片就绪后点击“处理后继续重试”恢复扫码；相册模式继续使用所选图片。下一次二维码提交使用当前用户的照片凭据，成功后清除，不能带给下一位用户。若还出现滑块，两个上下文会按同一用户和活动绑定后继续。

窗口关闭、页面离开、切到后台或迟到的相机授权都会释放相机。官方页面处理后可核对当前用户结果，再继续后续用户。普通失败仍按第 11 次移到队尾；等待照片、位置或滑块本身不计为失败。

## 验证边界

测试照片是程序生成的纯色图片，平台响应均使用离线模拟；未采集或上传真实人脸，也未提交真实签到 / 签退。覆盖跨用户隔离、取消与过期、签到和签退独立记录、照片与滑块联动及镜头释放 / 队列恢复。真实平台是否接受普通照片路径及是否另需官方活体，须按具体活动验证，不能仅据离线测试保证成功。

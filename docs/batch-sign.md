# 所有用户签到（v0.19.0）

签到中心上方提供二维码扫描、定位签到、手势 / 签到码和普通签到四个入口。

1. 默认全选可用用户；关闭“全选所有可用用户”后可在平铺列表中选择。
2. 定位、手势、普通方式点击“刷新所选用户签到活动”，检查所选用户的课程活动，按涉及人数排序，并使用全局昵称显示涉及用户。不同用户的不同活动不会混为一个活动。
3. 选择一个当前活动。普通签到无需额外参数；手势填写九宫格数字顺序，签到码填写当前活动的数字；定位选择预设点位或“使用设备位置上报”。已完成用户会跳过，不重复提交。
4. 点击“一键为所有适用用户签到”。服务器仅处理所选用户中有此活动的人，逐人记录成功、未成功、需要处理和不适用结果。并发沿用设置中的扫码签到并发数（默认5，上限20），与扫码共用全局提交资源及账号锁。
5. “停止剩余任务”阻止后续提交，已经发出的请求仍可能返回。失败可重试原活动的失败用户；滑块、人脸、照片等逐人要求用“单独查看 / 处理”打开原有单用户入口，不跨账号共用验证。

二维码扫描沿用连续扫码队列，支持全选用户及平台所要求的位置、滑块等条件。网页离开后批量普通 / 手势 / 定位任务会在服务器继续；注销或撤销 API 权限会停止尚未提交的任务。本次批量状态仅在服务器内存保留，最长15分钟，不跨服务重启恢复。页面刷新后可找回本浏览器身份的最近批次。

“使用设备位置上报”适用于安卓、iOS及桌面支持定位的浏览器。安卓v0.12.0优先使用原生系统定位，其他浏览器通过Geolocation API申请权限，需要HTTPS或本机localhost。每次开始获取新位置，不后台跟踪，不自动保存到预设点位。显示的是设备报告误差，桌面定位可能较粗；权限拒绝、定位超时或不可用时停止本次发起，不静默改用其他地点。浏览器能力见 [MDN](https://developer.mozilla.org/en-US/docs/Web/API/Geolocation/getCurrentPosition)。

与已有坐标方案一致，设备WGS84位置由服务器转换后用于当前批次；预设点位仍上报父类学校位置说明。全选时同一位置用于本次所有适用用户，请核对实际位置。定位不会改变活动的范围、人脸或其他验证要求。

插件 API：`POST /api/v1/batch-sign` 提交明确的 `account_ids`、`activity_id`、`kind`及所需参数；支持`normal`、`location`、`gesture`、`code`，二维码使用已有camera-stream。`GET /batch-sign/current`、`GET /batch-sign/{id}`及`POST /batch-sign/{id}/stop`均需`sign:write`，身份按密钥隔离。参数结构以OpenAPI / tools下载为准，位置和手势参数不在结果中返回。

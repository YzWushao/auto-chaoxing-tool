# 设备码绑定（v0.9.0）

“设置 → 设备码绑定”列出全部已管理的超星账户、完整设备码、来源和更新时间。它是本项目保存的请求参数，不是超星已认证设备列表，也不表示已通过平台的设备验证。

## 使用方式

- 每个未绑定账户自动生成一个独立随机码，加密保存在 SQLite。首次迁移和新增账户都会生成；刷新、重新登录、重新部署和进程重启不会改变它。普通失败、重复签到和二维码过期均不会自动换码。
- 逐个账户可粘贴设备码后保存，或明确点击“重新生成随机码并绑定”。已有课程、API、登录信息不因设备码修改而更改。
- “统一设备码”是新账户的默认值。勾选“同时覆盖以下所有现有账户”后才覆盖列表内账户；单独绑定可以随后覆盖它。清空统一默认值仅影响以后新增账户，已有绑定继续保留。
- “读取本机设备码（浏览器）”读取本浏览器、本网站存储的随机标识，首次使用生成并保存；点击按钮只填入输入框，保存后才生效。不会读取硬件序列号、OAID、IMEI、MAC、摄像头标识或进行浏览器指纹采集。清除本网站数据或更换浏览器会改变本地标识，服务器已保存的账户绑定仍保留。无持久存储权限时明确报错，不生成临时码冒充稳定标识。
- “读取手机分享二维码”在本机识别随地大小签分享图，只提取 `dc`，不打开二维码 URL，不上传图片、手机号、密码、姓名或设备信息。提取后需要点击保存，不能将包含账号凭据的整个链接粘贴为设备码。

网页、QQ、连续摄像头扫码和一次性链接的签到均使用相应账户保存的码，作为最终 `stuSignajax` 请求的 `deviceCode`。位置、验证码、签到/签退及照片处理沿用原逻辑；不修改刷课引擎。修改在新建请求上下文后生效，已经发出的请求保留其原参数。

所有读取/修改设备码的接口均需管理员会话与写操作 CSRF；一次性扫码链接不能访问设备码管理接口，也不会返回设备码。账户删除会同时清理该绑定。设备码和统一配置使用现有 Fernet 密钥加密存储，学校点位 JSON 不包含这些数据。

## 调研及来源

参考 [ChaoxingSignFaker 的设备码实现](https://github.com/aquamarine5/ChaoxingSignFaker/blob/0346adf72dde1d3fea5600232c575ad2211641c3/app/src/main/java/org/aquamarine5/brainspark/chaoxingsignfaker/api/ChaoxingDeviceInfoHelper.kt)和该版本签到请求字段，协议来源按 AGPL-3.0 引用。其手机读取方式依赖 Android 的 OAID，通过 AES/ECB 处理后编码；随机码采用重复的 32 字节值进行 Base64 编码，并随账户保存。本项目采用密码学随机字节生成同形状随机码，自行实现 Python 持久化和网页管理；不伪造 Android 原生设备证明，不采用上游重复签到后自动换码策略。

普通网页的媒体设备 `deviceId` 是站点隔离的设备标识，会随清除站点数据或无痕会话改变，不能把它当成上述手机设备码，详见 [MDN](https://developer.mozilla.org/en-US/docs/Web/API/MediaDeviceInfo/deviceId)。本项目不使用该 API 获取设备码。

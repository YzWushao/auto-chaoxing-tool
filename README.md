# auto-chaoxing-tool

超星多账户 Web 控制台，初期开发快照。独立管理员登录，进入后以手机号 / 密码或二维码连接超星账户，集中管理刷课、签到和配置。

## 运行

需要 Python 3.12 或更高版本。在项目目录执行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe run.py
```

浏览器访问 [http://127.0.0.1:8765](http://127.0.0.1:8765)。服务默认仅监听本机。停止服务使用 `Ctrl+C`。网页关闭后后台任务仍会运行，关闭服务会停止任务，重启后中断任务不会自动恢复。

首次使用默认管理员账号 **`admin`**、默认密码 **`admin`**。进入“设置 → 管理员账号与密码”修改登录名称或密码；修改需提供当前密码，新密码至少 8 位，保存后所有管理员会话失效，需要重新登录。不要使用默认密码开放局域网或公网访问。

管理员登录、添加 / 重新登录超星账户均使用可关闭的小窗，支持右上角关闭、取消按钮和 Esc。关闭超星窗口会停止二维码轮询、撤销该二维码等待，不会停止已有后台任务。超星密码只用于本次平台认证，不会保存到数据库。

## 当前功能

- 管理员登录：控制台认证与超星身份分离；管理员密码使用 scrypt 哈希保存，服务端会话令牌的哈希保存于 SQLite，30 天有效，支持退出撤销和改密后全部撤销。
- 超星登录：管理员进入后通过小窗添加账户；支持手机号和密码、学习通扫码确认。超星密码仅用于当前登录，不保存。
- 多账户：每个账户独立保存 Cookies、目标课程、学习参数与题库 / API 设置；支持继承工作空间全局 API 配置。
- 刷课：课程与班级分别选择；独立参数页；任务启动、停止、日志、进度、手动答题输入；每账户一个独立工作进程。
- 课程处理复用内置刷课引擎，包括视频 / 音频、文档、阅读、章节检测等已有处理路径。并发单位是课程，同一课程章节顺序执行。
- 签到：读取有效活动、普通签到，以及按需提供二维码 enc、签到码 / 手势数字、位置或已有图片 objectId。
- 二维码图片：在二维码签到弹窗选择本地 PNG / JPEG / WebP（最大 8 MB），浏览器本地解码并自动填入 enc 或原始内容；图片不上传服务器或第三方。支持手动修改后确认提交，不自动发起签到，也不额外做二维码活动编号匹配或过期判断；无效参数、活动结束、动态二维码过期等按后台 / 平台实际结果报错。
- 位置签到：点击“地图拾取坐标”，放大地图后点击选点或拖动标记，自动回填 6 位小数经纬度；支持“使用地图中心”和“按已填坐标定位”。“定位当前位置”仅在手动点击后请求浏览器定位权限，使用高精度模式并显示设备报告的误差半径；电脑定位可能较粗。不会自动提交签到。
- 坐标系：OpenStreetMap 底图使用 WGS84；回填默认采用签到参考项目所用的百度 BD-09，可切换高德 / 腾讯 GCJ-02 或 WGS84。转换在本地执行，切换只转换已选地图点，不静默改写手填值。平台要求以当前实际使用的坐标系为准；公开转换算法、底图和定位均可能有误差，6 位小数不代表实地分米精度。请核对实际位置和位置说明，不用于伪造出勤。
- 地图无需 API Key，首次展开才请求在线底图；新增 / 编辑预设点位直接展示可视化地图。可以点击选点、拖动标记，或拖动地图（停止时取中心坐标），搜索地点后再微调。底图需要能访问 `tile.openstreetmap.org`，失败时仍保留手填功能；不上传超星账户或 Cookies。遵守 [OSM 瓦片使用政策](https://operations.osmfoundation.org/policies/tiles/)，仅加载当前视野、不预下载或批量抓取，保留地图署名及浏览器缓存；公共服务无可用性保证，不适合大规模部署。
- 地点搜索使用 [Nominatim 公共服务及使用政策](https://operations.osmfoundation.org/policies/nominatim/)，这是本机小规模点位管理的可选外部服务，不是通用搜索平台。仅用户点击 / 按 Enter 才发送公开地点关键词，禁止自动补全、批量搜索、网格遍历和逆地理编码。后端使用独立无 Cookies 请求，标识本项目、全局串行且请求间隔至少 1.1 秒、同词缓存 24 小时（最多 1000 条缓存）；显示 OSM 署名。请勿输入私人住址或机密数据，搜索结果只是大致位置，需自行核对。`AUTO_CHAOXING_GEOCODER_URL` 可切换兼容 Nominatim 的 HTTPS 服务，设为空可关闭；服务不可用时仍可拖图。公开部署 / 多实例不能默认依赖公共额度，应改用自有或商业服务，并由部署者负责遵守服务政策。
- 预设点位：学校是父级、点位是子级。先点击“新建学校”创建父级（允许空学校），再在该学校下通过可视化地图新增点位；新增、编辑弹窗都支持搜索公开地名、拖动地图取中心点、点击选点和拖动标记微调。点位只能选择已建学校，不能通过填写学校名隐式建父级。位置签到弹窗也可新建学校并保存当前选点到已建学校；“设置 → 预设点位”可管理同一份学校 / 点位，支持学校重命名、学校删除（含子点位）、子点位增删改、JSON 导入 / 导出。
- 学校与已保存点位数量不设上限，删除最后一个点位不会删除其父级学校。点位内容在 SQLite 中加密持久保存（学校分组名称作为明文索引）；保存、应用、导入均不会提交签到。删除需确认，建议先导出备份。
- JSON：支持单所学校格式（见 `web/examples/location-presets.example.json`）及导出的 `{"version":1,"schools":[学校配置,…]}` 格式。每校有 `school`、`coordinate_system`、`points`；点位有 `name`、`longitude`、`latitude`、可选 `address` 和可选 `coordinate_system`（缺省继承学校坐标系）。同名学校导入前确认整校覆盖，批量导入原子保存；不同学校可有同名教学楼，同一学校点位名称唯一。单文件最大 8 MB，可按学校拆分导入；这是传输保护，不是保存数量限制。导出不含账号、Cookies 或 API 配置，可能包含你保存的位置，请自行保管。无预装学校实际点位。
- 本地事件：登录成功 / 失效、刷课结果、签到成功；SQLite 保存配置与任务记录，Cookies 和 API 配置加密保存。

当前版本为单管理员控制台；超星账户不再用于登录控制台。升级时将旧版已有工作空间授权给本机管理员管理，不改写旧账户 ID、加密 Cookies、账户配置、任务或签到记录；即使不同旧空间中有相同超星 UID，也保留各自的记录。旧浏览器中的超星身份会话不能绕过管理员认证。全局 API 沿用账户最多的旧空间配置，其余旧空间配置仍保存在数据库中；新保存的全局配置统一用于控制台内开启继承的账户。

从旧版本升级前，请在停止服务后备份完整 `data/` 目录（包括 `secret.key`）。更换代码后重启后端，新登录逻辑才会生效；刷新网页不等于重启后端。管理员更名或改密不会删除超星账户、修改其密码或停止任务。

在“设置”配置全局 API；在“刷课中心 → 刷课参数”设置当前账户自己的 API 或选择继承全局。未配置题库时默认不启用题库；自动提交章节检测默认关闭。更改配置对下次新任务生效。

### 视频计时与观看时长

默认“按时长学习”，并开启“从头计时，包含已完成的视频”。旧账户中缺少这两个新参数时也使用该默认值。每个账户可在“刷课参数”中独立更改。

- 按单调时钟经过的时间推进媒体位置，并定期调用原引擎的进度上报接口。平台提前返回任务点已通过，也不会提前结束本轮计时。
- 1 倍速时，20 分钟的视频需要约 20 分钟运行时间；2 倍速约需 10 分钟。网页显示媒体进度、实际运行计时和任务点确认结果。
- 重看已完成章节时，只重看媒体，不会重复提交已完成的章节测验。关闭“从头计时”后，按平台返回的已有位置续接，已完成任务按原规则跳过。
- “仅完成任务点”保留上游的完成即跳过和快速完成逻辑，可能很快结束。
- **后台运行计时不等同于平台已入账的观看时长**。该功能使用进度接口，不是在浏览器中呈现视频画面的播放器；平台最终如何记入课程学习统计，需要在官方页面核对。
- 没有实际完成媒体计时的任务不会仅因章节已完成就显示全部成功。停止任务保留已记录的进度，不会补满时间。

## 数据与部署

运行数据在 `data/`，工作进程的临时文件在其任务子目录。`data/console.sqlite3` 保存账户、加密平台凭据、管理员密码哈希和会话令牌哈希；`data/secret.key` 是本机数据加密与 Cookie 签名密钥，备份数据时需要连同密钥一起保存。浏览器也必须保留该站点的登录 Cookie 才能续用管理员会话；数据库无法恢复已清除的浏览器凭证，平台 Cookies 主动失效后仍需重新登录。不要提交运行数据、密钥、数据库、Cookies、日志或自己的配置到 GitHub。

环境变量 `AUTO_CHAOXING_DATA_DIR` 可更改数据目录；`AUTO_CHAOXING_ALLOWED_HOSTS` 可指定允许的主机名（逗号分隔）；HTTPS 反向代理部署时设置 `AUTO_CHAOXING_HTTPS=1`。服务可用 `--host`、`--port` 配置监听地址。当前版本以本机部署为默认使用场景，尚未完成公网多租户部署验收。

## 测试与当前限制

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest
```

`tests/` 使用离线平台响应和子进程夹具，不会提交真实签到或刷课请求。`python -m tests.preview` 仅用于离线页面检查，端口 8766；正式启动入口始终是 `run.py`。

二维码回归测试用 `qrcode` / Pillow 生成虚构二维码；有 Node.js 时额外运行真实 jsQR 解码与参数填入测试（正常使用项目不需要安装 Node.js）。`python -m tests.make_sign_qr_fixtures --output work/qr-ui-fixtures` 可生成用于离线页面验收的图片。

真实登录二维码的获取及等待扫码响应已检查。当前快照尚未使用真实账户完成整套刷课和所有类型签到的端到端验收，超星接口变化、验证码、二次验证或课程规则可能需要进一步适配。网页拍照签到目前需要已经上传的图片 objectId，尚未实现直接上传图片。OCR 可按需额外安装 `ddddocr`，未安装时保留引擎的无 OCR 处理方式。
